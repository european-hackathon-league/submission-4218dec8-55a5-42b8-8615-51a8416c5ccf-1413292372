Six changes for the RFQ agent, from the analysis of test run run_8614349eb83b71eb
(quality 78.8, 220 calls, $0.37, 7:39; package 26251a2d4a4a).

That run lost 21.2 points on two reading mistakes by the ERP worker; every other
field scored full. Line references are to that package: if the code has moved,
find the place by the quoted text.

Rule for all six: figures quoted below come from the practice websites and are
here only to explain. Code, tests and prompt text must use invented figures.

1. Remove the 25-second pause limit on model answers        [code only]
   Fact:   a tool-call answer arrives in one piece at the end, not bit by bit.
           Two healthy answers were thrown away about 26 s after they started
           and asked again: started 00:57.6 (30 s, 1,266 output tokens) and
           02:41.8 (28 s, 920 tokens). On a slower day every long answer would
           be lost this way.
   Change: rfq_agent.py: PAUSE_TIMEOUT = ANSWER_LIMIT (no separate pause limit)
           and FIRST_TOKEN_TIMEOUT = 60. The first piece of an answer arrives
           within about a second, so the first-token limit still catches a
           request that gets no response.

2. Put the copying rule back into the record guide          [prompt; needs a test run]
   Fact:   the ERP worker recorded two scale prices as '64.853' and '186.615'
           with number_format en-US. The page shows them with a comma as
           thousands separator and a format tag. The code then read 64.853, and
           three base prices came out 1,000 times too small (19.9 points with
           the unit prices, bonus and total that depend on them). No recorded
           price carried a format tag in this run; in the 100-point run they did.
   Change: pricing.py RECORD_GUIDE, the sentence "Report values only: no
           explanations or quotes (...)". Replace with: copy every number
           character for character as the page shows it, with its separators and
           the format tag printed next to it; never convert, round or
           re-punctuate a number; no explanations, a note of a few words only
           where indispensable.

3. Check recorded numbers against the page, in code         [code only; not built or tested yet]
   Fact:   catches the mistake of item 2 whatever the model does: '64.853' is
           nowhere on the page, '64,853' is.
   Change: rfq_agent.py worker(): keep the raw text of every tool result the
           worker received (before history trimming). In the record branch, for
           each value that is a number written with a separator, require that
           its number token occurs in that text (treat all kinds of space
           alike; skip date fields). If it does not, refuse the record and tell
           the model how the page writes the number with the same digits.
           Accept an identical second report, so a wrong check can never block
           a worker.

4. Open a collapsed section only when nothing visible matches   [code only; tested here offline]
   Fact:   browser_tools._locate opens the collapsed section of every candidate
           before checking visibility. Where a label occurs twice, once visible
           and once inside a closed section, the value goes into the hidden
           field and the step reports ok.
   Change: look for a visible field first, exactly as before the patch. Only
           when no control of that name is visible, search once more with the
           sections opened. Also widen FIELDS from [contenteditable=true] to
           [contenteditable]:not([contenteditable=false]).

5. Tell the mail worker when its "not authorized" flag decides  [tool reply; needs a test run]
   Fact:   in the 100-point run one worker flagged 7 genuine messages as not
           authorized because of a banner on the page; two other workers
           outvoted it. With one mail worker nothing does, and a wrong flag
           sets the discount to 0 or leaves gaps without any warning.
   Change: use the existing Evidence.warnings / "check" reply. When a mail
           record has authorized false, names this exact tender reference and
           is not dated after the scenario date, add: authorized=false alone
           keeps this message out of the calculation; that is right only when
           the sender or the subject is not the one the brief names for the
           topic; if the reason was anything else, record it again with
           authorized true.

6. Record both stock figures                                [prompt + code; needs a test run; least certain]
   Fact:   for three materials the worker recorded the stock total from the
           overview (95, 99, 139), which includes blocked stock, as
           available_stock. The available figures were 29, 31 and 51. One lead
           time came out as 1 week instead of 11 (1.3 points).
   Change: material record: add physical_stock next to available_stock, and say
           in the guide that available_stock is only what is free for delivery.
           Calculator: a material with physical_stock but no available_stock is
           a gap, so the worker is sent back for the breakdown.
